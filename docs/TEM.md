# Learning reusable structure with TEM

TEM separates a cognitive map into reusable structure **g** and sensory identity **x**.
Their conjunction **p** binds what was observed to the inferred structural location.
A fast Hebbian memory **M** stores these conjunctive patterns within each world.
Slowly trained weights learn transitions shared across worlds; memory resets between worlds.
This lets a model predict a previously seen observation through a new route in a new world.

```text
 action -> g -> p <- x
               | ^
               v |
                M    (Hebbian storage and attractor retrieval)
```

## Run and inspect

From the repository root, with the package and development dependencies installed,
run these three commands:

```bash
python -m pytest tests/tem -q
python examples/tem_whittington.py --steps 400
python experiments/tem_overnight_report.py
```

Measured wall times on this Mac: 29.23 s, 9.07 s, and 1.26 s respectively.
These measurements overlapped other validation jobs; they are approximate run costs.
The short example checks execution, not the overnight training result.
The report aggregates supplied JSON records; it does not retrain models.
The spiking example (`python examples/spiking_tem_kawahara.py`) took 57.69 s.
Its theta oscillation is imposed, and its small run is not a paper reproduction.

## Four changes that stabilized training

- **Missing L_p_x and mis-scaled objective:** supervising sensory-cued memory and
  calibrating loss reductions restores the intended balance between reconstruction,
  latent consistency, and activity costs.
- **Reliability-blind fusion → reliable_fusion:** memory correction is weighted by
  retrieval reliability so an unreliable recalled pattern does not overwhelm path integration.
- **Unbounded attractor → bounded activation:** bounding recurrent retrieval prevents
  growing activations from destabilizing memory and gradients.
- **Compressed memory curriculum:** gradually increasing memory use lets sensory
  compression and transition learning develop before full associative retrieval is required.

These are implementation choices tested here, not four independently established causal
results: v1 groups objective and activation changes; v2 adds reliability-aware fusion.

## Results

Accuracy is **our internal metric**: first visit to a seen node via a new directed edge,
in 4×4 and 8×8 worlds. Values below are regenerated by the report command from completed
records, with three training seeds per variant and 16,000 optimizer updates per seed.
The spread is sample standard deviation across training seeds.

| Variant | Accuracy, mean ± SD | Best baseline | Report verdict |
|---|---|---|---|
| v0 | 0.2358 ± 0.1499 | 0.1027 | FAIL |
| v1 | 0.7211 ± 0.0377 | 0.1027 | PASS (R2 claimed) |
| v2 | 0.7687 ± 0.0073 | 0.1027 | PASS (R2 claimed) |
| v3v0, rotation imposed | 0.8315 ± 0.0141 | 0.1027 | PASS (R2 claimed) |
| v3v1, rotation imposed | 0.7833 ± 0.0480 | 0.1027 | PASS (R2 claimed) |

“R2 claimed” is the report's coordinate-probe criterion, not a grid-cell classification.

## What this does and does not show

- Better than our earlier model (v0) and than the sensory-only/frequency baselines on our
  internal metric. NOT shown better than the paper: we did not score the authors' model on
  this metric. Their public-default code, run once for 40k iterations, stayed near chance
  in next-observation loss (about 2.1-2.5 against ln 10 = 2.30); ours reaches 1.0-1.15.
  Different code and worlds, one seed: indicative only. v0 is our reference-schedule
  implementation, not an authors' checkpoint.
- This metric is not comparable to the paper's gridness/remapping analyses.
- Gridness is not measurable at 8×8 under the library's resolution criterion.
- v3 builds in group structure, so periodicity there is imposed, not learned.
- Model weights were not saved, so no spatial-tuning comparison with the authors'
  checkpoint has been made yet; the supplied JSONs support behavioral aggregation only.
- Three seeds and small discrete worlds limit generalization; the spiking extension
  needs separate spatial and temporal validation.

## Spatial tuning probe

Training runners now save portable weights and configuration every 500 updates and at
completion in `experiments/results/checkpoints/<variant>-s<seed>.pt`; override the interval
with `--checkpoint-every`. These snapshots omit optimizer and transient memory state.
Load with `neurosush.tem.checkpoint.load_checkpoint` (restricted `weights_only=True`).

Run `PYTHONPATH=src python experiments/tem_spatial_probe.py --checkpoint PATH --out PREFIX`
or `PYTHON=python sh experiments/run_spatial_probe.sh` for every saved checkpoint.
Omit `--checkpoint` for the random-init control. JSON and Markdown share the reference
analysis table columns: occupancy-weighted spatial information, permutation and circular
shift null means, active-unit fractions above each unit's null p95, split-half Pearson r,
five-block nearest-template accuracy (25-sample gap) and fixed-prediction shift-null p95,
cross-world per-unit map correlation, population-distance RSA with node-permutation null,
and distance correlations against Manhattan grid distance and sensory mismatch.

Defaults use four new 8x8 worlds, seed 1000000, 3000 transitions, 300 burn-in samples,
32 SI shuffles and 100 decoder/RSA null samples. Each world starts with empty memory;
slow weights are frozen. Position and sensory metadata are aligned with the current
inferred g, prior g_gen, and bound p_inf. The coordinate ridge probe in the earlier
report is a different metric. World sizes, sensory vocabulary, walks, and random-number
streams differ from the reference experiment; matching metrics alone is not a matched
training comparison. Use evaluation seeds disjoint from training world seeds.

The reference SI formula accepts signed activations and clamps the mean at 1e-12.
Our latent activations can be signed: this can produce enormous values even at random
initialization, so those entries are reference-formula diagnostics, **not interpretable
bits/spike**. No rectification or baseline subtraction is silently applied. Random-init
controls can also decode position because fast memory binds observations within a world.
High within-world tuning alone therefore does not establish learned spatial geometry.
Missing/constant correlations are JSON null (Markdown nan). Unvisited decoder templates
retain the reference's zero-distance nansum behavior; inspect occupancy metadata.
Gridness and hex-versus-square classification are unresolvable at 8x8 (`resolvable=False`).
The rotation variant has imposed structure; none of these measurements demonstrates that
grid cells emerged or that this implementation beats the paper.

Completed smoke measurements are in `experiments/results/tem-spatial-random.{json,md}`.
The completed 500-update v2 seed-1 pipeline check is in
`experiments/results/tem-spatial-500.{json,md}` (three worlds, 1800 transitions).
Full retraining spatial results are pending.

## Retraining and 16x16 Commands

Exact commands for retraining v2 seeds 1 and 2 and running a 16x16 world model (with checkpoints every 500 updates):

- `--snapshots 500,2000,4000,8000,16000` controls trajectory snapshot intervals saved as `<variant>-s<seed>-u<update>.pt`.
- Snapshots beyond the requested `--updates` count are automatically skipped.
- The final update is also saved as a snapshot if it differs from the milestone checkpoints.

```bash
# Retrain v2 seed 1 (16000 updates, checkpoints every 500)
nohup PYTHONPATH=src python experiments/tem_overnight_v1.py --variant v2 --seed 1 --updates 16000 --out experiments/results/overnight/v2-s1.json --checkpoint-every 500 > v2-s1.log 2>&1 &

# Retrain v2 seed 2 (16000 updates, checkpoints every 500)
nohup PYTHONPATH=src python experiments/tem_overnight_v1.py --variant v2 --seed 2 --updates 16000 --out experiments/results/overnight/v2-s2.json --checkpoint-every 500 > v2-s2.log 2>&1 &

# 16x16 world run (seed 0, 16000 updates, checkpoints every 500)
nohup PYTHONPATH=src python experiments/tem_overnight_v1.py --variant v2 --seed 0 --size 16 --updates 16000 --out experiments/results/overnight/v2-s16-s0.json --checkpoint-every 500 > v2-s16-s0.log 2>&1 &
```

## Recorded run export

To generate compact JSON run records (`tem-run.json`, schema version 1) for the site viewer,
run the exporter CLI:

```bash
PYTHONPATH=src python experiments/tem_record_run.py --checkpoint experiments/results/checkpoints/v2-s0.pt --out site-data/tem-run-v2-s0.json
```

This loads checkpoint weights with restricted unpickling, runs walks across evaluation worlds with
fresh fast memory per world, selects the most position-informative units for `g` and `p`, and exports
rate maps, walk coordinates, prediction correctness, and first-visit new edge indicators while ensuring
the file stays compact (<300 KB).
